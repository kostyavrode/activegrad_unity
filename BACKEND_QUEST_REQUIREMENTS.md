# Требования к Backend для системы квестов

## Обзор

Backend должен предоставлять API для получения ежедневных квестов, отслеживания их выполнения и выдачи наград.

---

## 1. Структура данных квеста

### Модель Quest (обязательные поля)

```json
{
  "id": 1,                    // int - уникальный идентификатор квеста
  "type": "mark_sights",      // string - ОБЯЗАТЕЛЬНО! Тип условия квеста
  "title": "Отметься в 3 местах",  // string - название квеста
  "description": "Посети 3 разные достопримечательности",  // string - описание
  "count": 3,                 // int - требуемое количество для выполнения
  "reward_type": "coins",     // string - тип награды: "coins", "experience", "item"
  "reward_amount": 100        // int - количество награды
}
```

### Обязательные поля:
- ✅ **`id`** - уникальный идентификатор (int)
- ✅ **`type`** - тип условия квеста (string) - **КРИТИЧЕСКИ ВАЖНО!**
- ✅ **`title`** - название квеста (string)
- ✅ **`description`** - описание квеста (string)
- ✅ **`count`** - требуемое количество для выполнения (int)
- ✅ **`reward_type`** - тип награды (string)
- ✅ **`reward_amount`** - количество награды (int)

### Типы условий квестов (type):

| Тип | Описание | Пример |
|-----|----------|--------|
| `mark_sights` | Отметка в достопримечательностях | Отметься в N местах |
| `visit_sights` | Альтернативное название для mark_sights | (маппится на mark_sights) |
| `steps` | Пройти N шагов | Пройди 10000 шагов |
| `collect_coins` | Собрать N монет | Собери 500 монет |
| `level_up` | Достичь уровня N | Достигни 5 уровня |

**Важно:** Поле `type` **НЕ МОЖЕТ** быть пустым или null. Если тип не указан, квест не будет обработан на клиенте.

### Типы наград (reward_type):

| Тип | Описание |
|-----|----------|
| `coins` | Монеты |
| `experience` | Опыт |
| `item` | Предмет (требует дополнительного поля `item_id`) |

## 2. API Endpoints

### 2.1. Получение ежедневных квестов

**Endpoint:** `GET /api/quests/daily`

**Headers:**
```
Authorization: Bearer {access_token}
```

**Response (200 OK):**
```json
{
  "quests": [
    {
      "id": 1,
      "type": "mark_sights",
      "title": "Отметься в 3 местах",
      "description": "Посети 3 разные достопримечательности",
      "count": 3,
      "reward_type": "coins",
      "reward_amount": 100
    },
    {
      "id": 2,
      "type": "mark_sights",
      "title": "Отметься в 5 местах",
      "description": "Посети 5 разные достопримечательности",
      "count": 5,
      "reward_type": "experience",
      "reward_amount": 50
    },
    {
      "id": 3,
      "type": "steps",
      "title": "Пройди 10000 шагов",
      "description": "Сделай 10000 шагов за день",
      "count": 10000,
      "reward_type": "coins",
      "reward_amount": 200
    }
  ]
}
```

**Response (401 Unauthorized):**
```json
{
  "detail": "Authentication credentials were not provided."
}
```

**Требования:**
- ✅ Квесты должны обновляться ежедневно (новые квесты каждый день)
- ✅ Все квесты должны иметь поле `type` (не пустое, не null)
- ✅ Квесты должны быть уникальными для каждого дня
- ✅ Количество квестов может варьироваться (обычно 3-5 квестов в день)

---

### 2.2. Подтверждение выполнения квеста (опционально)

**Endpoint:** `POST /api/quests/{quest_id}/complete`

**Headers:**
```
Authorization: Bearer {access_token}
Content-Type: application/json
```

**Request Body:**
```json
{
  "player_id": 123
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "message": "Quest completed successfully",
  "reward_given": {
    "type": "coins",
    "amount": 100
  },
  "player_stats": {
    "coins": 500,
    "experience": 150,
    "level": 5
  }
}
```

**Response (400 Bad Request):**
```json
{
  "success": false,
  "message": "Quest already completed"
}
```

**Response (404 Not Found):**
```json
{
  "success": false,
  "message": "Quest not found"
}
```

**Примечание:** Этот endpoint опционален, так как клиент может отслеживать выполнение локально и выдавать награды автоматически. Но рекомендуется для синхронизации с сервером.

---

### 2.3. Получение прогресса квестов (опционально)

**Endpoint:** `GET /api/quests/progress`

**Headers:**
```
Authorization: Bearer {access_token}
```

**Response (200 OK):**
```json
{
  "quests_progress": [
    {
      "quest_id": 1,
      "current_progress": 2,
      "required_count": 3,
      "is_completed": false,
      "reward_claimed": false
    },
    {
      "quest_id": 2,
      "current_progress": 5,
      "required_count": 5,
      "is_completed": true,
      "reward_claimed": true
    }
  ]
}
```

**Примечание:** Этот endpoint опционален, так как клиент сохраняет прогресс локально. Может быть полезен для синхронизации между устройствами.

## 3. Логика работы

### 3.1. Ежедневный сброс квестов

- Квесты должны обновляться каждый день в 00:00 UTC (или по локальному времени сервера)
- Старые квесты удаляются, создаются новые
- Прогресс по старым квестам не сохраняется (ежедневные квесты)

### 3.2. Валидация данных

Backend должен валидировать:
- ✅ Поле `type` не пустое и не null
- ✅ Поле `count` > 0
- ✅ Поле `reward_amount` >= 0
- ✅ Поле `reward_type` из списка допустимых значений
- ✅ Все обязательные поля присутствуют

### 3.3. Обработка ошибок

Если квест невалиден (например, отсутствует `type`):
- Backend должен либо не возвращать такой квест
- Либо возвращать с флагом `"valid": false` (если нужна дополнительная информация)

## 9. Важные замечания

### ⚠️ Критически важно:

1. **Поле `type` ОБЯЗАТЕЛЬНО** - без него квест не будет обработан
2. **Поле `type` не может быть пустым** - пустая строка = ошибка
3. **Поле `type` не может быть null** - null = ошибка
4. **Типы должны совпадать** с зарегистрированными на клиенте (или быть в маппинге)

### ✅ Рекомендуется:

1. Использовать константы/enum для типов квестов
2. Валидировать данные перед отправкой
3. Логировать ошибки валидации
4. Предоставлять понятные сообщения об ошибках
