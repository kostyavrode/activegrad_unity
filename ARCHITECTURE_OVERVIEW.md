# Архитектура проекта ActiveGrad Unity

## Общая информация

- **Unity версия**: 6000.2.9f1 (Unity 6)
- **Платформа**: Android (mobile)
- **Название проекта**: activegrad
- **Архитектурный паттерн**: Dependency Injection (Zenject) + MVP/MVVM

## Структура проекта

### Основные директории

```
Assets/
├── _Project/              # Основной код проекта
│   ├── Core/             # Ядро приложения
│   ├── UI/               # Пользовательский интерфейс
│   ├── Audio/            # Аудио система
│   ├── Prefabs/          # Префабы
│   └── Other/            # Вспомогательные компоненты
├── Mapbox/               # Интеграция карт Mapbox
├── Plugins/              # Внешние плагины (Zenject, AR Foundation)
└── Resources/            # Ресурсы (персонажи, одежда)
```

## Архитектурные слои

### 1. Dependency Injection (Zenject)

Проект использует **Zenject** для управления зависимостями. Основные установщики:

#### `ProjectInstaller` (глобальный контекст)
- Регистрирует основные сервисы:
  - `APIService` - работа с REST API
  - `SceneLoader` - загрузка сцен
  - `UIManager` - управление окнами
  - `UserDataService` - хранение данных пользователя
  - `CharacterPreviewService` - превью персонажа
  - `PopupService` - система всплывающих окон
  - `AudioManager` - управление звуком

#### `UIInstaller` (контекст сцены)
- Регистрирует окна текущей сцены
- Инициализирует `UIInitializer`

#### `LoadingSceneInstaller`
- Установщик для сцены загрузки

#### `OtherInstaller`
- Дополнительные зависимости

### 2. Core Layer (Ядро приложения)

#### 2.1 Services (Сервисы)

**APIService** - Центральный сервис для работы с бэкендом
- Базовый URL: `http://87.228.97.188/api/`
- Функционал:
  - Регистрация/авторизация пользователей
  - Управление токенами (access/refresh)
  - Обновление одежды персонажа
  - Получение квестов
  - Поиск игроков
  - Работа с достопримечательностями (sights)
  - Магазин (покупка предметов)
- Автоматическое обновление токенов при 401 ошибке

**LocationService** - Сервис геолокации
- Интерфейс: `ILocationProvider`
- Реализация: `GPSLocationProvider`
- Получение координат пользователя

**MapService** - Работа с картами
- Интеграция с Mapbox
- Загрузка статических карт через Yandex Maps API
- Обновление карты на основе GPS координат
- Реализует `ITickable` для периодического обновления

**SightService** - Сервис достопримечательностей
- Интерфейс: `ISightService`
- Интеграция с Wikipedia API
- Загрузка ближайших достопримечательностей
- Получение детальной информации о достопримечательностях
- Кэширование изображений
- Компоненты:
  - `WikipediaApiClient` - клиент для Wikipedia
  - `SightItemFactory` - фабрика для создания объектов достопримечательностей
  - `SightsUpdater` - обновление списка достопримечательностей

**CharacterService** - Управление персонажем
- `CharacterService` - основной сервис
- `CharacterController3D` - контроллер движения
- `CharacterPreviewService` - превью персонажа
- `ClothingApplier` - применение одежды

**UserDataService** - Хранение данных пользователя
- Сохранение в `PlayerPrefs`
- Управление профилем пользователя:
  - Авторизационные данные (токены)
  - Профиль (имя, уровень, опыт, монеты)
  - Одежда персонажа
  - Посещенные достопримечательности
  - Ежедневные шаги (с автосбросом)

**ImageLoadService** - Загрузка изображений
- Интерфейс: `IImageLoadService`
- Асинхронная загрузка изображений из URL

**PopupService** - Всплывающие окна
- Интерфейс: `IPopupService`
- Показ ошибок и уведомлений

**PlayerInputService** - Обработка ввода игрока

**GamePopupService** - Игровые всплывающие окна

#### 2.2 Loaders (Загрузчики)

**AppLoader** - Инициализация приложения
- Автоматический вход (если есть сохраненные данные)
- Загрузка главной сцены
- Управление начальным экраном (Login/Main)

**SceneLoader** - Загрузка сцен
- Асинхронная загрузка сцен Unity

#### 2.3 Camera

**CameraController** - Управление камерой

### 3. UI Layer (Пользовательский интерфейс)

#### 3.1 Архитектура UI

Используется паттерн **Mediator** для разделения логики и представления:

```
Window (View) ←→ Mediator ←→ Services/Managers
```

#### 3.2 Базовые компоненты

**UIManager** - Центральный менеджер окон
- Регистрация окон сцены
- Управление стеком открытых окон
- Навигация между окнами
- Показ/скрытие окон

**BaseWindow** - Базовый класс для всех окон
- Реализует интерфейс `IWindow`
- Управление видимостью через `CanvasGroup`
- Виртуальные методы `OnShow()` / `OnHide()`

**IWindow** - Интерфейс окна
- `Show()` / `Hide()` - показ/скрытие
- `IsVisible` - состояние видимости

#### 3.3 Windows (Окна)

Все окна наследуются от `BaseWindow`:

1. **LoginWindow** - Экран входа
2. **RegisterWindow** - Регистрация
3. **MenuWindow** - Главное меню
4. **ProfileWindow** - Профиль игрока
5. **SettingsWindow** - Настройки
6. **QuestWindow** - Квесты
7. **SightsWindow** - Список достопримечательностей
8. **ShopWindow** - Магазин
9. **PlayerSearchWindow** - Поиск игроков
10. **CharacterCustomizationWindow** - Кастомизация персонажа

#### 3.4 Mediators (Медиаторы)

Медиаторы связывают окна с бизнес-логикой:

- **LoginMediator** - логика входа
- **RegisterMediator** - логика регистрации
- **MenuMediator** - навигация из главного меню
- **ProfileMediator** - управление профилем
- **SettingsMediator** - настройки
- **QuestMediator** - квесты
- **SightsMediator** - достопримечательности
- **ShopMediator** - магазин
- **PlayerSearchMediator** - поиск игроков
- **OtherPlayerProfileMediator** - профиль другого игрока
- **CharacterCustomizationMediator** - кастомизация

Все медиаторы реализуют:
- `IInitializable` - инициализация при создании
- `IDisposable` - очистка подписок

#### 3.5 Views (Представления)

- **SightItemView** - элемент списка достопримечательностей
- **SightDetailsView** - детали достопримечательности
- **QuestItemView** - элемент квеста
- **ShopItemView** - элемент магазина
- **OtherPlayerProfileView** - профиль другого игрока
- **OtherSightsView** - достопримечательности другого игрока
- **OtherPlayerSightsDetailsView** - детали достопримечательности другого игрока
- **PopupView** - всплывающее окно

### 4. Audio System

**AudioManager** - Менеджер звука
- Управление музыкой и звуковыми эффектами
- Реализует интерфейс для управления громкостью

**AudioSettings** - Настройки аудио

**AudioInstaller** - Установщик аудио системы

## Поток данных

### Инициализация приложения

```
1. BootstrapInstaller (запуск)
   ↓
2. ProjectInstaller (глобальные зависимости)
   ↓
3. AppLoader.Start()
   ↓
4. Проверка авторизации
   ├─→ Если авторизован → LoadMainSceneAsync()
   └─→ Если нет → Show<LoginWindow>()
```

### Навигация между окнами

```
User Action → Window Event → Mediator Handler → UIManager.Show<T>()
```

### Работа с API

```
Mediator/Service → APIService → UnityWebRequest → Response
                                      ↓
                              (401?) → RefreshToken() → Retry
```

## Особенности архитектуры

### Сильные стороны

1. **Разделение ответственности**
   - Четкое разделение на слои (Core, UI, Services)
   - Медиаторы изолируют бизнес-логику от представления

2. **Dependency Injection**
   - Легкое тестирование
   - Слабая связанность компонентов
   - Централизованное управление зависимостями

3. **Асинхронность**
   - Использование async/await для API запросов
   - Неблокирующие операции

4. **Кэширование**
   - Кэш изображений в SightService
   - Сохранение данных пользователя

### Области для улучшения

1. **BootstrapInstaller** - пустой класс, возможно не используется
2. **Обработка ошибок** - можно улучшить централизованную обработку
3. **Логирование** - используется Debug.Log, можно добавить систему логирования
4. **Конфигурация** - API URL захардкожен, лучше вынести в конфиг
